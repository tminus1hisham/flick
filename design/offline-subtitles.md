# External subtitles with downloads

Open a completed download while online, open Subtitles, select an external caption, then choose **Save subtitle offline**. This saves the caption that was actually loaded for that downloaded video. Embedded tracks already stay in the video. The feature uses the existing downloaded-player routes; it does not add a download queue or an automatic subtitle-language guess at enqueue time.

The shared phone/TV panel provides save/replace, remove, Find online subtitles, busy feedback and inline Retry. Buttons wrap in narrow panels, use 48dp targets and the house TV focus/reveal controls. Save retains focus; when Retry or Remove disappears, focus returns to Find online subtitles. Changing the selected external file resets stale save-retry actions.

`StreamDownload` and legacy `Download` records preserve stream-provided subtitle candidates. Older records read an empty candidate list and can still find addon subtitles. HTTP, kept-torrent and legacy-torrent playback pass the exact download ID, candidates and saved local caption to the shared player; video request headers remain empty for local playback.

`Downloads` owns `OfflineSubtitles`, a serialized on-device sidecar store. `downloadSubtitles` records the download ID, label, language and validated generated filenames under the app's `offline-subtitles` directory. It stores no absolute path, remote caption URL or video credentials. A save journals its new filename before writing, then commits it as active only after the UTF-8 file is flushed. Failed replacement leaves the previous active caption intact. Interrupted/failed writes remain associated with the download so deletion can clean them up. Replacement cleans old files; cleanup references survive failed deletions for Retry. Deleting the video removes its sidecars through every download backend. A deletion tombstone prevents a pending save from recreating the record.

On restart the directory is resolved afresh and the saved file loads through `SubtitleTrack.data`. A saved caption is preferred without contacting subtitle servers; global Subtitles Off and a current manual choice still win. Find online subtitles explicitly requests fresh choices. Only the trusted saved file may be read locally: addon-provided `file:` URLs are rejected. Missing/corrupt files produce the existing visible subtitle-load error and Retry while video playback remains available.

External caption fetching remains isolated from video headers and now has a 20-second timeout plus a 2 MiB response bound, including responses without Content-Length. UTF-8 and legacy Latin-1 text are supported. Saved text is bounded to 2 MiB in UTF-8. Native embedded captions and the current ASS/image-renderer limitations are unchanged; saving does not bake session timing offsets into subtitle timestamps.

Automated checks cover store reload, replacement, failed metadata commits, interrupted saves/deletion races, cleanup for all three download backends, corrupt/path-traversal records, missing/oversized files, header isolation and chunked-response bounds. Route tests inspect saved-file/candidate/header arguments after restart without mounting native mpv. Phone/TV widget checks cover larger text, remote activation, save-retry feedback and focus recovery. Physical airplane-mode playback after app restart, real-provider formats, native deletion failures and TalkBack/remote acceptance remain backlog item 5 device checks.
